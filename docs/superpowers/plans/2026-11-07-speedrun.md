# /speedrun Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `aaronsulbaran.com/speedrun`: an opener in Aaron's style, a one-second shift into a speedrun-styled product demo, and a working concept of what a talent-network member gets on day one (matches, a board built from their inbox, a morning brief), backed by a real retrieval system with an optional live model.

**Architecture:** One App Router route. Server Components render the acts; one client root (`SpeedrunDemo`) owns the demo's state through a pure reducer. All logic (snapshot, extraction, matching, inbox classification, pipeline, flow data, brief) is pure TypeScript in `lib/speedrun/` with vitest tests. Two Node API routes (resume read, brief send) are optional layers that switch on with env vars; without them the page runs on deterministic code and five sample people.

**Tech Stack:** Next.js 16.2 App Router, React 19.2, TypeScript strict, Tailwind 3.4 over CSS custom properties, zod 4, a hand-rolled flow layout (no d3: the public export strips it), AI SDK (new, via the Vercel AI Gateway), unpdf (new, PDF text), Resend over plain HTTP (no SDK), vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-07-speedrun-design.md` (read it first; this plan argues from it). Brand values: `docs/research/inspiration/2026-11-06-speedrun-talent-network.md` (gitignored; read it from the worktree path the controller gives you).

## Global Constraints

- No em dashes anywhere: code, comments, copy, tests, commit messages.
- Every user-visible string lives in `lib/content/speedrun.ts` (exported through `lib/content.ts`); components never embed strings. Act 1 copy is first person in Aaron's voice.
- No hex in components. Colors are CSS custom properties in `app/globals.css` mapped in `tailwind.config.ts`. Act 2's tokens live under `[data-speedrun]` only.
- Nothing under `app/speedrun`, `components/speedrun`, `lib/speedrun`, `public/speedrun` or `scripts/speedrun-snapshot.mjs` imports from `components/recruiting`, `lib/recruiting`, `lib/hacktx`, `app/recruiting`, `app/hacktx2026` or reads `docs/content`.
- All people, inboxes and resumes are made up. Negative events (rejection, no reply) only name fictional companies from `lib/speedrun/fictional.ts`; real speedrun companies appear only as listings and matches.
- Public mirror words: these paths replay into a public repo whose verify step rejects, in any public file, path, identifier, comment, test name, copy or commit message, the strings `recruit` (any case, except the words recruiter and recruiters), `sankey` (any case), `second brain`, `ledger feed`, `ledger export`, `application ledger`, `--viz-`, `viz-lane`, any `/Users/<name>/` path, and key-shaped strings like `sk-...`. Name the chart a "flow" (`toFlow`, `FlowChart`) and Aaron's dashboard "my job search dashboard". Never write those words in commit messages either.
- No `d3-*` packages in speedrun code: the public export strips `d3-sankey` and `d3-shape` from `package.json` and the lockfile, so the public build would fail. The flow layout is hand-rolled in `lib/speedrun/flowLayout.ts`.
- Live switches are explicit flags, not key presence: on Vercel the AI Gateway authenticates through an automatic OIDC token, so a key check alone would turn spend on. Reading is live only when `SPEEDRUN_AI === "on"`; email only when `SPEEDRUN_EMAIL === "on"` and `RESEND_API_KEY` and `SPEEDRUN_EMAIL_FROM` are set.
- Their font files are never added. Lookalikes only: Inter Tight (sans) and Roboto Condensed (labels, buttons), via `next/font/google`, scoped to the route.
- Their API: never per visitor; only the snapshot script calls it, at most 1 request per 1.2 s, `?source=portfolio-research`, user agent `Mozilla/5.0 portfolio-research`. Never request any URL containing `-ad00000`. On a Cloudflare challenge or HTTP 403/429/1015 body, stop and exit non-zero.

- Reduced motion: every animation has a `prefers-reduced-motion: reduce` branch (no movement, static end state).
- Components under about 200 lines; pure modules under about 300.
- Commits: small, staged by name (never `git add -A`; `docs/content/` is private), message ends with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` for implementers.
- Shell safety: never `pkill`, `killall` or pattern kills; stop only a PID you saved from `$!`. Never touch ports 3220 or 3221. Your build port is the one the controller gives you.
- Playwright: take a slot first with `mkdir "/private/tmp/claude-501/-Users-asulbaran21-Personal-Projects-Personal-Website/1c9e7db2-62bc-4db0-af9a-bd2cfcb919a3/scratchpad/pw-slots/slot1"` (or `slot2`), release it with `rmdir` on the same literal path the moment the run ends; if both are taken, do other work and retry later. ## Review Focus

1. A visitor with JavaScript disabled or reduced motion: the whole page reads top to bottom with Act 2 already styled; nothing is hidden behind the shift.
2. No keys set (the default on day one): every flow completes on samples and the deterministic code, and the UI says live reading turns on later instead of erroring.
3. A hostile or odd resume upload (empty file, a 30 MB PDF, an image-only PDF, plain text, a non-English resume): the route returns a typed error or the rules fallback, never a 500 with a stack.
4. A pasted email that matches nothing: the classifier returns `other`, the flow chart does not change, and the UI says it could not tell.
5. Phone width (390 px): the shift, the join card, the flow chart and match cards fit with no horizontal scroll.

Limits: 5 reads per 10 minutes per address and 300 a day per instance. Never logs resume text; logs errors as `[speedrun] read failed: <code>`.
